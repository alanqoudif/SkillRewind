# SkillRewind API Stability — v1

**Status:** v0.3 alpha. This document categorizes every route in the live `/api/v1` surface (see
`docs/openapi-v1.json`, generated by `make openapi` from the real FastAPI app — never hand-written) as
`stable-v1`, `experimental-v1`, or `internal`, and defines the compatibility rules for `stable-v1`.

## Categories

- **`stable-v1`** — covered by the compatibility rules below. Breaking changes require a new major API version
  (`/api/v2`). This is what `docs/integration-contract-v1.md` builds on.
- **`experimental-v1`** — real, tested, and usable today, but may still change shape or be removed without a
  major version bump while v0.3 is alpha. Research/benchmark tooling, not part of the cross-platform
  integration contract.
- **`internal`** — operator/administrative surface. Requires the `admin` scope or is a local-development
  convenience; not intended for external platform self-service and may change without notice.

## Compatibility rules for `stable-v1`

1. **Existing fields are not silently removed.** A field present in a `stable-v1` response today will remain
   present (though it may be deprecated with advance notice) until a `/api/v2` major version.
2. **Enum values are versioned carefully.** New enum values (e.g. a new `resolution` value, a new evidence
   class) may be added; existing values are never repurposed to mean something different. A client that
   switches on known values and has a default/`unavailable`-style fallback for unknown ones remains forward
   compatible.
3. **New optional fields may be added** to any `stable-v1` request or response at any time without a major
   version bump. Clients must ignore unknown fields.
4. **Semantics are documented.** Every `stable-v1` endpoint's behavior is described in
   `docs/integration-contract-v1.md` and/or its route's own docstring in `src/skillrewind/api/routers/`; a
   semantic change to a documented behavior (not just a schema change) is also a breaking change requiring a
   major version.
5. **Breaking changes require a new major API version.** Removing a field, changing a field's type, repurposing
   an enum value, or changing documented semantics in a way an existing client would observe requires
   `/api/v2`; `/api/v1` keeps working under the rules above for the lifetime of the v1 contract.
6. **No indefinite-stability promise beyond this stated v1 contract.** This is a v0.3 **alpha** contract: the
   rules above are the compatibility bar SkillRewind holds itself to *while `/api/v1` exists*, not a promise
   that `/api/v1` itself is supported forever. `experimental-v1` and `internal` routes carry no such guarantee
   at all.

## Idempotency

Mutating `stable-v1` endpoints that create a durable resource (`POST /api/v1/artifacts`,
`POST /api/v1/derivations/{id}/output`, `POST /api/v1/revocations`, `POST /api/v1/waivers`) accept an
`Idempotency-Key` header; replaying the same key with the same request body returns the original resource
(`idempotent_replay: true` in the response where applicable) rather than creating a duplicate. See
`src/skillrewind/api/idempotency.py`.

## Error shape

All error responses use RFC 9457 Problem Details (`about:blank` type, `title`, `status`, `detail`) — see
`skillrewind.api.deps.ProblemDetail`. This shape is itself part of the `stable-v1` contract: existing fields
(`type`, `title`, `status`, `detail`) are not removed.

## Auth

Bearer API keys (`Authorization: Bearer srw_<prefix>_<secret>`), scoped (`ingest`, `read`, `replay`, `revoke`,
`waive`, `admin`). Scope requirements per endpoint are visible in `docs/openapi-v1.json`'s `security`
definitions. See `docs/threat-model.md` for key handling and revocation.
