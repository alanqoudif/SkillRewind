# Security Policy

SkillRewind is a research preview (v0.2.0). It has not undergone external security review and should not be deployed against production credentials, untrusted third-party artifacts, or live agent traffic without further hardening.

## Supported versions

| Version | Supported |
|---|---|
| 0.2.x | Yes (current research preview) |
| 0.1.x | No (superseded research starter) |

## Reporting a vulnerability

Please report suspected vulnerabilities privately rather than opening a public issue. Open a GitHub security advisory on this repository (Security tab → "Report a vulnerability"), or contact the maintainer directly through the contact information in `CITATION.cff`. Include:

- a description of the vulnerability and its potential impact;
- reproduction steps or a minimal proof of concept;
- the affected version/commit.

We will acknowledge reports within a reasonable timeframe and coordinate disclosure before any public write-up. Please do not publish exploit details for a newly discovered vulnerability before a fix is available.

## Known limitations relevant to security

- The `SandboxedSubprocessRunner` (`skillrewind.replay.sandbox`) does not provide real network-namespace isolation. It sanitizes the environment and applies CPU/memory/process rlimits on POSIX, but a process inside it can still make outbound network calls if the underlying OS permits it. Only allowlisted, trusted fixture recipes should ever be routed through it. Prefer `DeterministicFixtureRunner` for anything not fully trusted.
- No HTTP API, authentication, or authorization layer exists in this release — the CLI and library API assume a trusted, single-operator local environment.
- Ed25519 private keys generated by `skillrewind attest-keygen` are written with `0600` permissions but are otherwise unprotected (no OS keychain integration). Do not commit them; `.skillrewind/keys/` should be gitignored in any project that uses this tool.
- The candidate scorer and verification suites operate on content you provide; malicious `SKILL.md` frontmatter is parsed with `yaml.safe_load` (not `yaml.load`) specifically to avoid arbitrary object deserialization, but always review skills from untrusted sources before ingesting them.
